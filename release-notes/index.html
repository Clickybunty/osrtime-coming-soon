Release Notes

Updates, fixes and improvements to OSRTIME Sync-Box TCR.

1.0.2 — Expanded USB 24-Bit Support & Audio Format Display

Available on Google Play.

What changed?

This update expands 24-bit recording support for tested USB audio interfaces and improves audio level monitoring and the recording format shown in Settings.

Some USB interfaces expose audio to Android through a 32-bit integer capture format. OSRTIME Sync-Box TCR can now use this capture path and convert the samples to 24-bit PCM for recording.

What we fixed

  • Expanded 24-bit recording support for tested USB audio interfaces, including the Behringer UMC204HD and Zoom UAC-232.
  • Corrected audio level calculations when capturing audio through Android’s 32-bit integer format.
  • Corrected the active format display in Settings to reflect the audio output format used by the app.
  • Removed the misleading “fallen back to 32-bit” message when the app is correctly producing 24-bit PCM.
  • Preserved the existing USB detection safeguards and 16-bit fallback when Android rejects a requested higher-resolution recording mode.

About 24-bit recording through a 32-bit capture format

The format Android uses to capture audio does not always match the format saved in the recording.

For compatible devices, OSRTIME Sync-Box TCR can capture 32-bit integer samples and convert them to 24-bit PCM. In this case, Settings correctly shows 24-bit as active. This is a planned format conversion, rather than a fallback to 32-bit recording.

This path uses integer PCM and does not provide 32-bit float recording.

Tested during this development cycle

Manual testing on a Xiaomi Redmi Note 11 included:

  • Behringer UMC204HD
  • Zoom UAC-232
  • DJI Mic 3
  • USB-C to 3.5 mm audio adapters
  • Creative Sound Blaster Play! 3
  • Wired 3.5 mm microphone input

The supported recording format depends on the connected device and the format Android makes available. The wired 3.5 mm input was tested at 16 bit.

Additional checks confirmed 24-bit PCM WAV files containing 1, 2, 3 and 4 recorded channels, matching the selected recording channels. Multichannel recording remains an existing feature.

Compatibility notes

Support has been verified for the tested configurations. This does not guarantee 24-bit compatibility with every USB audio interface or Android device.

A 24-bit file describes the stored digital sample format. The effective resolution and dynamic range also depend on the connected hardware and Android’s audio path.

32-bit float recording is not included in this update.

Device feedback & support

Thank you to everyone contributing device tests and feedback. If you encounter unexpected behaviour, please let us know at support@osrtime.com which Android device and audio interface you used, which recording format you selected, and what happened.

1.0.1 — Audio Routing & 24-Bit Stability Update

What changed?

This update focuses primarily on external audio devices, USB audio routing, and 24-bit recording stability.

During beta testing, we discovered that Android audio devices can report 24-bit support in different ways. A device may appear to support 24-bit audio while Android is not necessarily able to open that particular format through the same recording path. Previously, attempting to switch to 24-bit in such a situation could leave the audio system in an unstable state or cause the audio path to stop responding.

What we fixed

OSRTIME Syncbox TCR now handles these situations much more safely.

  • Improved detection and handling of external USB audio devices.
  • Improved switching between built-in, wired, and USB audio inputs.
  • Improved handling of 16-bit and 24-bit audio capabilities.
  • Added support for 24-bit recording on compatible USB audio devices.
  • Devices that cannot currently start the requested 24-bit format can safely fall back to 16-bit instead.
  • Fixed an issue where attempting to use an unsupported 24-bit configuration could leave the audio system unresponsive.
  • Improved stability when connecting, disconnecting, and manually selecting external audio devices.

About the 16-bit fallback

If you select 24-bit and OSRTIME Syncbox TCR reports that it has fallen back to 16-bit, this is a normal compatibility behavior and does not indicate a crash or malfunction.

Because different USB audio devices expose 24-bit audio to Android differently, support depends on both the connected hardware and the audio format Android makes available to the app. Rather than forcing an incompatible configuration that could freeze the audio system, OSRTIME Syncbox TCR now safely and seamlessly falls back to a working 16-bit format.

We are continuing to expand compatibility with additional 24-bit USB audio implementations.

Tested during this development cycle

Testing included several different input configurations, including:

  • Built-in Android microphone
  • Wired 3.5 mm microphone input
  • USB-C to 3.5 mm audio adapters
  • DJI Mic 3
  • Creative Sound Blaster Play
  • Behringer UMC204HD
  • Zoom UAC-232

The purpose of testing different devices is not only to support individual products, but to make the audio system more robust across the wide variety of USB audio hardware available for Android.

Beta testing continues

OSRTIME Syncbox TCR is still being actively tested. If you encounter unexpected behaviour, a device that does not work correctly, or a workflow that could be improved, please let us know.

Real-world testing across different Android devices and audio hardware directly helps us improve compatibility and stability before release.

Thank you to everyone participating in the OSRTIME Syncbox TCR beta and contributing feedback, hardware tests, and bug reports.
